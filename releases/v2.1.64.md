## Features

- **make container-prefix a universal tunable, starting with cd-release.yml's package jobs (#1139)**
* feat(package): apply container-prefix to cd-release.yml's package-build cells

The ci-package.yml images step moves into a shared composite action, actions/package/image-prefix (action.yml plus apply.sh), which both matrix jobs now run: ci-package.yml's matrix job and cd-release.yml's package-matrix job. cd-release's package-build cells now take the <prefix>-pkg- images from the workflow's existing container-prefix input; prod (and empty) pass the matrix through byte for byte, any other value fails package-matrix. package-image-prefix.test.sh now checks both workflows' wiring and the action, and runs apply.sh, including an empty matrix for a repo without [package]; package-runtime.test.sh takes cd-release's build output from the images step. Ref #1134

* feat(ops): add a container-prefix input to ops-upstream-refresh.yml

The upstream-refresh job ran on a fixed prod-base image and the workflow had no inputs. It now declares the optional container-prefix input (prod or dev, default prod) and runs on <prefix>-base:latest like the other ops workflows, so a caller can move it to the dev images on its own. Callers that pass nothing are unchanged. Ref #1134

* test(workflows): check that every reusable workflow honours its container-prefix

container-prefix.test.sh scans every workflow_call workflow in .github/workflows: no string names a ghcr.io/vergil-project/prod- image literally, every job container is a <prefix>- image or a matrix image produced by ci/matrix or package/image-prefix given the workflow's input, every call to a workflow of this repo that declares the input passes it on, and a workflow running any such job declares the input (string, optional, default prod). Fixture workflows check that each rule catches its violation. smoke-setup-vergil.yml runs it. Ref #1134

* docs(workflows): document container-prefix as a per-workflow tunable

cd-release's binary packages page gains a Container prefix section and its input row now says the prefix also picks the package-build images; ci-package's section points to the shared action; ops-upstream-refresh documents its new input; the workflows overview and README state the rule every reusable workflow follows; and package/image-prefix gets its own action page. Ref #1134
