# Release 2.1.91 (2026-11-23)

## Bug fixes

- **skip the Python dev install on a repo not bootstrapped yet (#1367)**
  Route every Python leg's dependency install in ci-quality, ci-test and ci-audit through a new ci/toolchain/install-python action. It skips uv sync with a notice when neither pyproject.toml nor uv.lock exists, the same strict test vrg-validate uses (vergil-tooling#4384), so PR CI reaches vrg-validate's loud skip. A partial bootstrap or a failing uv sync still fails the step. Ref #1206.
- **accept a proved not-bootstrapped gate skip in evidence report staging (#1373)**
  * fix(ci): accept a proved not-bootstrapped gate skip in evidence report staging

  A gate vrg-validate skipped because the repo is not bootstrapped yet passes having written no report, so the stage step failed it. Stage mode now accepts such a leg only when the vrg-validate record is of HEAD, exited 0 and shows every stage warn, every manifest of the language is missing and there are no sources; it prints a notice and stages a skip record in place of the reports. Expect mode accepts a quality gate's skip records in place of its reports. Any leg that fails the proof fails on its missing reports as before. Ref #1294.

  * fixup! fix(ci): accept a proved not-bootstrapped gate skip in evidence report staging

## Documentation

- **move the remaining cron examples to the fleet's current hours (#1281)**
  The ops-upstream-refresh and cd-docs-refresh examples move to the 01:xx UTC hour, matching the generated ops.yml (vrg-github-repo-init schedules minute 1) and the docs repository's cd-docs-refresh.yml (17 1). The ops-epic-sweep example moves to 02:00 UTC, not 01:xx: the real caller, the org .github epic-sweep.yml, runs at 0 2 so the sweep follows the 01:xx ops runs, keeping the one-hour gap the old 06:xx/07:00 pair had.
- **fix the markdownlint errors in the Scorecard snapshots (#1287)**
  docs/security/openssf-scorecard-snapshots.md now passes markdownlint under the fleet's bundled config (the one vrg-validate uses): bare URLs are wrapped in angle brackets (MD034), each Warnings list has a blank line before it (MD032), and the collapsed <details> blocks become plain bold Info details labels (MD033). The MD013 and MD060 errors the issue lists come from markdownlint's default config; the bundled config turns both rules off, so they are not errors under the fleet's lint and are left as they are. Whether docs/security/ joins the lint scope is not decided here: the scope is fixed in vergil-tooling's validate_common, not in this repository.
- **drop the Dependabot itemized-report, self-homed sweep and GHAS-condition passages (#1372)**
  Every repository is now public and vergil-tooling v2.1.336 ships the behaviour these passages still described as removed: the Dependabot log carries counts only, the epic sweep no longer moves self-homed queue items, and the code-scanning checks carry no GHAS condition. Update the docs pages and the two workflow comments to match. Ref #1370.
- **list the release tag token step in the Requested permissions table (#1374)**
  The token-scoping table omitted the cd-release.yml release job's Mint release tag token step, which requests contents: write. Checked against every create-github-app-token step on develop; this was the only one missing. Ref #1371
