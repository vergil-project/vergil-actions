
# Release 2.1.6 (2026-07-01)

## Bug fixes

- **deploy un-versioned site when versioning-scheme=none (#714)**
Docs repos with versioning-scheme=none (single-branch org docs sites) were
still deployed through mike, producing a versioned site: a 'dev' version with
the current content plus an init '0.1'/'latest' version frozen at scaffold.
The root redirected to /dev/, but /latest/ (and /0.1/) served stale content,
and the /dev/ URL prefix and version selector are meaningless for a repo with
one branch and no versions.

Read versioning-scheme from vergil.toml (same [project] read used for
primary-language). When it is 'none', skip mike entirely and publish a single
plain site to the gh-pages root via 'mkdocs gh-deploy --force' — no version
split, no versions.json, no selector. --force replaces the branch, so the
prior dev/0.1/latest fragments are cleaned up on the next deploy. Versioned
repos are unchanged.
