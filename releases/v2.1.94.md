# Release 2.1.94 (2026-11-24)

## Bug fixes

- **leave a not-bootstrapped leg's tools out of its gate's evidence.json (#1407)**
  Tools mode of ci/evidence/reports takes an optional reports-dir. Given the evidence job's downloaded legs, a gate whose legs staged not-bootstrapped skip records lists no tools, with a notice, checked as expect mode checks the skip records; a refused skip record fails loudly. ci-test, ci-audit and ci-quality pass evidence-reports, so the release bundle names no tool that never ran. Refs #1406.

## CI

- **read the automation App secrets from the automation environment (#1398)**
  * ci(workflows): read the automation App secrets from the automation environment

  The cd.yml docs, ops.yml github-config and epic-rollup.yml callers pass secrets: inherit in place of their explicit App-key maps, since environment secrets reach a reusable workflow only under inherit. Ref vergil-project/vergil-actions#1388

  * test(ops-report): require secrets inherit on cd.yml's local cd-docs call

  The reporting-jobs guard checked for the explicit App-key map that the automation environment supersedes; it now requires secrets: inherit, and a fixture shows an explicit map is caught. Ref vergil-project/vergil-actions#1388

- **run the smoke harnesses nightly and report failures to the operations queue (#1401)**
  A vergil-tooling release that breaks a harness surfaced only when an unrelated pull request ran that smoke workflow. nightly-harnesses.yml calls every smoke-*.yml once a day and reports the run as harness-nightly through ops/report. check-nightly-harnesses keeps every smoke workflow in the run. Ref #1399

## Features

- **add the reusable daily agent audit workflow (#1409)**
  * feat(protected-paths): protected-path registry

  Name actions/** as this repository's protected paths, on top of the fleet's protected core (vergil-project/vergil-actions#1341, epic vergil-project/.github#1384 Task 13).

  * feat(ops): the daily agent audit

  Add the reusable ops-agent-audit.yml, which runs vrg-agent-audit for its calling repository as the automation App in the automation environment, from develop only, in a full-history clone, with a repo-scoped token of Contents write and Pull requests, Issues and Metadata read.
