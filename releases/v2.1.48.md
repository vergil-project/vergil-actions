
# Release 2.1.48 (2026-10-22)

## Bug fixes

- **fail a requested publish whose credential is missing, and drop Ruby (#988)**
The Publish step now runs publish.sh, which fails with an ::error:: naming the secret when the credential vrg-ecosystem-resolve names is empty, instead of skipping with a notice and letting the release report success. A credential name the action does not provide (vergil-tooling and vergil-actions disagree) also fails loudly. The accepted names are the env vars the publish tools read: CARGO_REGISTRY_TOKEN (cargo publish) and MAVEN_GPG_PASSPHRASE (maven-gpg-plugin).

Remove the Ruby leftovers (rubygems-api-key, GEM_HOST_API_KEY, the RUBYGEMS_API_KEY secret and ruby in the build-and-publish condition); vergil-tooling#3388 removed Ruby support.

Add tests/publish.test.sh, run by the new smoke-registry-publish workflow, covering the credential check and the secret -> input -> env var wiring.

## Features

- **derive CI versions through vrg-ci-resolve and assert the running toolchain (#990)**
* feat(setup): derive CI versions through vrg-ci-resolve and assert the running toolchain

derive.sh now runs vrg-ci-resolve once and copies its answer to the setup action's outputs, adding container-tags and container-suffixes; the inline Python derivation is gone and resolver errors fail the step as ::error:: annotations. ci/matrix builds every image from the resolver's tags and suffixes with no family routing, and run-once kinds follow the primary version. A new ci/toolchain/assert action checks that each matrix leg runs its resolved Python or Go version, after the leg pins UV_PYTHON. Ref vergil-project/vergil-actions#962

* chore(setup): mark the resolver and toolchain-assert scripts executable

Restores the executable bit on derive.test.sh and sets it on the new assert.sh and assert.test.sh, matching the sibling action scripts. Ref vergil-project/vergil-actions#962
