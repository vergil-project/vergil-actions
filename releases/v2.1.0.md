
# Release 2.1.0 (2026-06-04)

## Bug fixes

- **treat missing origin/main as a first-release no-op**
A repo with no origin/main is in a legitimate bootstrap / pre-release state: nothing ships without main, so there is no published version to diverge from. The fetch step previously ran 'git fetch origin main' unconditionally, which exits 128 (couldn't find remote ref main) and failed the whole version-bump job, permanently blocking PRs on repos whose only long-lived branch is develop. The gate now probes the remote with 'git ls-remote --exit-code': a genuinely absent main is treated as a first-release no-op (job goes green), while real fetch/network errors (any other non-zero exit) remain fatal so they are not masked. The compare step already tolerated an empty main version. Closes the hard-failure described in issue #672.
