
# Release 2.1.50 (2026-10-22)

## CI

- **pin the docs jobs' uv interpreter source with UV_PYTHON_PREFERENCE=only-system (#1005)**
* ci(docs): pin the docs jobs' uv interpreter source with UV_PYTHON_PREFERENCE=only-system

The ci-docs and cd-docs jobs ran uv run mkdocs/mike for Python repos without UV_PYTHON_PREFERENCE, so a repo with python-preference = only-managed made uv download a managed Python for the docs build, or fail when it also set python-downloads = manual. Both jobs now set UV_PYTHON_PREFERENCE=only-system in their job env (source only; they resolve no version, so UV_PYTHON stays unset). The cd/docs/deploy action pins its Deploy docs step for direct callers, and setup/vergil pins the vergil-tooling self-install uv sync inline. The pin.test.sh harness gains a uv source guard: every workflow job running a uv project command or ci/toolchain/assert must pin first (pin-python or job env), and every composite action or script must pin on the step or inline, with assert (caller-pinned) and package/setup/detect.sh (needs managed Python) as listed exceptions; fixtures test the guard both ways. smoke-setup-vergil now triggers on any workflow or action change. Ref vergil-project/vergil-actions#1002
