
# Release 2.1.54 (2026-10-23)

## Bug fixes

- **derive single-container job image suffixes from the resolver (#1034)**
ci-quality's common job and ci-version-bump's version-bump job built their image suffix from the caller's container-suffix (else base), so a C++ or TypeScript caller passing no suffix ran on prod-base, and a Java or Rust caller on the unpublished prod-base:<version>. Both setup jobs now run the primary-suffix action on the shared setup action's primary-version and container-suffixes, and the jobs run on prod-<container-suffixes[primary]>:<primary-container-tag>, the image CI's primary leg uses (clang-20 -> prod-cpp-clang:20). The caller's container-suffix stays a must-match cross-check. The action now serves CI and CD, so it moves from actions/cd/release/primary-suffix to actions/shared/setup/primary-suffix; cd-release, its harness and the docs follow with unchanged behaviour. The new image.test.sh harness, run from smoke-setup-vergil, checks the wiring of all three single-container jobs, that no workflow job builds its image from inputs.container-suffix or inputs.language, the resolved images for C++, TypeScript, Python and no-language fixtures, and loud failure on mismatched caller suffixes. Ref #1028
