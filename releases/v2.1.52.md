
# Release 2.1.52 (2026-10-23)

## Bug fixes

- **test the warning passthrough with a stub resolver; app multi-pin is fatal (#1023)**
The released resolver (vergil-tooling 2.1.259+) makes an app pinning more than one version a fatal error (T14, vergil-tooling#3372) and prints no warnings (vergil-tooling#3442), so the derive.sh harness case that expected a ::warning:: for that pin failed on every PR. Replace it with a case that drives derive.sh's warning passthrough through a stub vrg-ci-resolve (same five-key JSON shape), add a case asserting the app multi-pin fails with the resolver's ::error::, and update the derive.sh comment and action docs. Ref #1022.

- **derive the release container tag from the resolver (#1024)**
The release job ran on the caller's container-tag input, which vrg-repo-init freezes into cd.yml at init time, so releases built on a stale version outside the window. A new setup job runs the shared setup action (vrg-ci-resolve) and the release job's image, and its validate-inputs check, now use its primary-container-tag, as CI's single-container jobs do. The container-tag input stays for one release as accepted-but-ignored with a ::warning::, because GitHub rejects an undeclared input to a reusable workflow and every caller still passes it; vergil-project/vergil-tooling#3484 removes it from the callers. Adds the container-tag.test.sh harness and smoke-cd-release workflow, and a cd-release workflow docs page. Ref #1017
