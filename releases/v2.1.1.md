## Documentation

- **add v2.0→v2.1 canary design (#679)**
Design for piloting the fleet-wide vergil 2.0→2.1 migration in vergil-actions as the lowest-risk, self-referential canary. Records the pin-driven cache mechanism, the two-line functional change, verification flow, risk surface, and the lockstep generalization that feeds the fleet playbook (vergil-tooling#1371).

- **revise v2.0→v2.1 canary design after pushback (#679)**
Pushback review surfaced four corrections: the version-divergence gate requires a VERSION bump (pin-only PR fails CI); a stale absolute action ref (standards-compliance setup/vergil@v2.0) must become @develop; acceptance splits into a CI gate and a CD gate because the PR never runs the release path where the 2.1 deltas live; and the doc scope includes the README @v2.0 consumer examples. Adds the two-version-axes explanation and folds the new lessons into the fleet generalization.

- **drop unneeded VERSION bump from canary design (#679)**
Verified origin/main=2.1.0 and develop=2.1.1, so a feature branch off develop already diverges from main and the version-divergence gate passes without a VERSION bump. Removes the erroneously-added VERSION change, returning the set to three changes (pin, standards-compliance ref, docs), and records the divergence-state check as the general rule.

- **expand canary doc scope to full @v2.0 sweep (#679)**
Discovered ~66 stale @v2.0 consumer references (11 in the workflows README, 55 across the published docs site) beyond the originally-scoped handful. Per decision, the canary does a full sweep of current consumer-facing refs to @v2.1, excluding historical records under docs/specs and docs/plans.

- **add v2.0→v2.1 canary implementation plan (#679)**
Task-by-task plan for the three-change set (tooling pin, standards-compliance @develop ref, full consumer-doc @v2.0 sweep), local validation gate, and PR/CI gate, with the CD gate and playbook implementation as follow-ups.

- **note no-auto-close-keyword PR constraint (#679)**
The standards-compliance check (vrg-pr-issue-linkage) rejects Closes/Fixes keywords, so migration PRs must link the issue without them. Captured in the CI-gate section and flagged as a per-repo playbook item; surfaced during alignment review of the implementation plan.

- **bump consumer @v2.0 references to v2.1 (#679)**
Sweep all current consumer-facing version refs onto the v2.1 line: CLAUDE.md host-install (v1.4 to v2.1), 11 refs in the workflows README, and 55 across the published docs site. Historical records under docs/specs and docs/plans are left as point-in-time records.
