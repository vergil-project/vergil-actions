
# Release 2.1.16 (2026-07-13)

## Bug fixes

- **split cd-release evidence into pre-publish gate + post-release attach (#777)**
T9 (#769) ran the whole CI-evidence step first, but two things it needs are
created later in the same job: the GitHub Release (gh release upload's target,
created by tag-and-release) and the SBOM (built by registry-publish). So in
warning mode the upload warned and attached nothing, and the bundle omitted the
SBOM. Split the single ci-evidence composite in two:

- ci-evidence-gate (stays first, pre-publish): resolve the release PR, harvest
  the required gate evidence, and validate completeness. Once enforcing,
  incomplete evidence fails here before anything is published (spec §9).
- ci-evidence-attach (new, after tag-and-release): assemble the complete bundle
  now including the built SBOM, attest it, and upload it to the Release that now
  exists.

Both composites invoke the existing vrg-ci-evidence bundle CLI and keep the
warning-mode contract: set +e captures the exit code so any failure/timeout
becomes a ::warning:: and exits 0, and the call-site continue-on-error tracks
evidence-enforce so even the uses: attest step cannot abort the release.
Promotion to enforcing (T11) stays a pure flip of the evidence-enforce default,
which flips both steps' fatality and both continue-on-error guards at once.
