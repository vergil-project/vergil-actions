# Release 2.1.93 (2026-11-23)

## Bug fixes

- **grant the update token Actions read for the automation environment (#1392)**
  GitHub serves the environment and deployment-branch-policy reads only to a token with Actions read. Without it, update cannot check the automation environment that vergil-tooling#4773 adds to the desired config. Ref #1387

## CI

- **read the automation App secrets from the automation environment (#1389)**
  Every job that reads a secret able to write or act (the automation App keys, CARGO_REGISTRY_TOKEN) now declares environment: automation, with its steps unchanged. scripts/bin/check-secret-environments, run by validate-custom and tested by scripts/tests/secret-environments.test.sh, fails on any job that reads such a secret outside its environment and on any secret it does not classify. Ref vergil-project/vergil-actions#1339.

## Documentation

- **name the publish command, order and consumers (#1391)**
  * docs(trusted-authors): name the trusted-authors publish command, order and consumers

  Name vrg-trusted-authors publish and render in the configuration and getting-started pages, give the setup order, and list VRG_TRUSTED_AUTHORS on every workflow page whose workflow passes it to a step. Ref #1386.

  * docs(trusted-authors): give the trusted-authors publish order the plan sets

  Install the trust-layer release on the host, then publish right away: publish ships in that release, so it cannot run before it. Ref #1386.

Reword the secret's description and the audit step comment in ci-audit.yml, the cpp caller example in the workflows README, and the ci-audit docs page to match. Wording only; the secret stays required: false. Ref #1375
