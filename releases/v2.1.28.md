
# Release 2.1.28 (2026-08-13)

## Bug fixes

- **provide GH_TOKEN to cd-docs pre-deploy step (#845)**
The pre-deploy step runs vrg-roadmap / vrg-activity-log, which shell out to gh to read the org .github epics. In an Actions runner gh exits non-zero without a token, so every CD docs-refresh job failed. The org .github epic home is public, so the repo-scoped default token is sufficient; set GH_TOKEN: ${{ github.token }} on the step. No wrapper or caller changes needed. Ref vergil-project/.github#310.


## Documentation

- **capture OpenSSF Scorecard as point-in-time snapshot doc (#841)**
Add docs/security/openssf-scorecard-snapshots.md capturing OpenSSF Scorecard as dated snapshots rather than accreting findings in the issue tracker. Preserves the 2026-05-19 baseline (5.5/10) and adds a freshly re-run 2026-08-12 snapshot (5.5/10, commit bbaccdd4). Format and location mirror the vergil-claude-plugin capture. - **update the all-hard-gates CI-evidence example to enforcing (#843)**
The CI-evidence completeness gate reached its enforcing end state after a ~4-week bake (evidence-enforce flipped false->true, live as of v2.1.27). The worked example in the all-hard-gates principle doc still described it in present-tense warning mode, which is stale. Rewrite the example as a lifecycle that ran to completion — introduced in warning mode, baked while robustness was validated, then promoted by a single flag flip to enforcing — and state the present end state plainly: an incomplete or failed evidence bundle is now a terminal, publish-blocking failure. Also document that completeness is now measured against report payload, not just envelope presence (ref #2812), and note the two current residuals (empty manifest metrics, empty security tools) as open limitations.
