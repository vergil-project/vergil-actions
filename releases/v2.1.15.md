
# Release 2.1.15 (2026-07-13)

## Bug fixes

- **pass GH_TOKEN to the docs stage step so evidence links resolve (#772)**
The 'Stage changelog and release notes' step runs vrg-docs-stage, which links each release page to its CI-evidence bundle via 'gh release view'. Its env block set only MKDOCS_CONFIG, so gh was unauthenticated and the docs job failed. Wire GH_TOKEN: ${{ github.token }} into the same env block; both docs workflows already grant the required contents permission. The nav-patch step (vrg-docs-patch-nav) makes no gh calls and is unchanged. Ref #770


## Features

- **harvest, attest, and attach CI evidence (warning mode) (#771)**
Add the actions/cd/release/ci-evidence composite and wire it as the first
publish step of cd-release.yml (evidence-first, spec §9). Ships in WARNING
mode (spec §9.2): non-fatal and timeout-bounded so it can never abort a
release; promotion to enforcing (Task T11) is a single flip of the
evidence-enforce default.

The composite runs vrg-ci-evidence bundle (bounded by the coreutils timeout
command, since composite steps cannot use timeout-minutes), attests the bundle
digest via actions/attest-build-provenance, and attaches the tarball plus
manifest with gh release upload --clobber. Bundle and upload are bash steps
that capture the exit code under set +e and, in warning mode, convert any
failure or timeout into a ::warning:: and exit 0. The attest step is a uses
step that a composite cannot wrap, so the call-site continue-on-error tracks
evidence-enforce, keeping warning mode non-aborting even on a rare attest
failure.

Add actions: read to the cd-release job permissions so the harvest can list
and download the release PR's ci-evidence-* artifacts (spec §5.2); the
consuming repo's cd.yml must grant the same scope.
