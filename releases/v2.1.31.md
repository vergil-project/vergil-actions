
# Release 2.1.31 (2026-08-24)

## Bug fixes

- **use python3 from PATH, not /usr/local/bin (#863) (#864)**
The 'Detect release model' step invoked /usr/local/bin/python3. That path exists in the base/python images - where this workflow's own ci.yml self-test runs (container-suffix: base) - but NOT in prod-cpp-clang:20, where python3 is at /usr/bin/python3. So the version-bump job hard-failed for any cpp repo with 'No such file or directory', before evaluating any version.

Confirmed in the cpp image: /usr/local/bin/python3 is absent; python3 from PATH is /usr/bin/python3 (3.13.5, tomllib present) and reads release-model correctly. Using python3 from PATH resolves to the right interpreter in every image and makes the step image-agnostic - the workflow should not assume a python location.

Surfaced by logical-minds-foundry/mq-protocol-gateway#1 (first cpp repo): PR #12 was green on every job except version/version-bump, purely because of this path.
