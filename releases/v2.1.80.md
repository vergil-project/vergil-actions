# Release 2.1.80 (2026-11-17)

## Bug fixes

- **give the install-tooling suite's CI-only reason its real cause (#1227)**
  The validation image does have python3, in /usr/local/bin. The suite skips locally because its missing_pin_fails case runs the real read-pin.sh with PATH limited to the stubs, /usr/bin and /bin, where the image has no python3. The CI-only reason now says so, and the suite's header lists the python3 it needs.

## CI

- **key the CD concurrency group by branch (#1277)**
- **run vergil-actions CI on the prod container images (#1282)**
  Drop container-prefix: dev from the quality, security and version jobs in ci.yml, so they fall back to the prod default. Running this repo's CI on the dev images was a one-off change that was never reverted; the standing rule is that CI runs on the prod images and the dev images are used only tactically. Ref #1275

## Documentation

- **document the App secrets as org secrets, not per-repository (#1272)**
  APP_CLIENT_ID and APP_PRIVATE_KEY are org-level Actions secrets visible to all repositories. The Secrets intro, App setup step 9 and the onboarding checklist now say so; per-repository secrets remain only as the fallback for an org without them. Ref vergil-project/vergil-actions#1268
- **move the example ops.yml cron to the 01:xx UTC hour (#1276)**
  vrg-github-repo-init now generates the nightly ops cron in the 01:xx UTC hour (vergil-project/vergil-tooling#4386), so the example in the ops-github-config page follows it.

## Features

- **name --python 3.15 on every vergil-tooling install and sync (#1283)**
  The git installs (uv_git_install, install-source: git, dev pins with no core Python) pass --python 3.15. The self-repo sync on a host runner passes --python 3.15 and drops UV_PYTHON_PREFERENCE=only-system so uv provides the interpreter; in a container it still pins the image's Python (issue #1002). The uv source guard in pin.test.sh exempts that one host sync line by exact match. Task 2 of epic vergil-project/.github#1256.
