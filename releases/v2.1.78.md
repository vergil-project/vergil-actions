
# Release 2.1.78 (2026-11-16)

## CI

- **drop the semgrep extra-config copy of the cpp and typescript rulesets (#1253)**
vrg-semgrep-scan resolves p/c for cpp and p/typescript for typescript from --language alone since vergil-tooling#4447 (released in v2.1.318), so the per-language extra-config in the semgrep job is redundant. The C++ coverage rationale now lives in vergil-tooling's lib/semgrep.py. Ref #1250.


## Documentation

- **use the versioned /latest/ path in links to the docs site (#1254)**

## Features

- **derive lint and typecheck evidence per language and require the reports (#1251)**
* feat(evidence): derive lint and typecheck evidence per language and require the reports

reports.sh gains lint and typecheck contracts for Python and Rust and an expect mode. Each ci-quality lint and typecheck leg stages through it, so a passing leg with no report fails, and the evidence job requires every report and takes the language's tools from it. A repository with no fleet primary language gets a notice on its quality legs. Refs #1249.

* fixup! feat(evidence): derive lint and typecheck evidence per language and require the reports

- **release TypeScript repos (#1261)**
- **run the BUILD check in the quality workflow (#1262)**
Add a build job to ci-quality.yml that runs vrg-validate --check build once on the primary version, only when vrg-ci-resolve reports build-enabled true. The setup action passes the flag through (an older vergil-tooling without it gives false), and the evidence job checks the build result against the flag with the new ci/evidence/assert action, whose decision lives in the tested build-gate.sh. Ref vergil-project/vergil-actions#1259.

- **stage TypeScript test, audit, lint and typecheck reports (#1263)**
* feat(evidence): stage TypeScript test and audit reports

reports.sh gains TypeScript test, audit, lint and typecheck contracts (coverage.xml and junit.xml, npm-audit.json, quality-eslint.json, quality-tsc.txt) and their tools, matching vergil-tooling's TYPESCRIPT_REPORT_FILES, and stops warning for TypeScript. report_tools now fails as an internal error for a contract language with no tools entry, so a contract can never emit an empty tools list silently. Refs #1260.

* fixup! feat(evidence): stage TypeScript test and audit reports
